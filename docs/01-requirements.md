# 01 · 需求

## 用户与目标

**用户**：内容运营人员。
**目标**：在给定**预算**与**截止时间**内，完成一份内容活动方案 —— 检索素材、生成脚本、估算成本、保存方案，并产出清晰的**任务计划、步骤状态、费用合计、已保存方案或未完成原因**。

**非目标**：真实发布、预算财务结算、多用户并发协调。

## 范围

| 做 | 不做 |
|---|---|
| 素材检索 / 脚本生成 / 成本估算 / 方案保存 | 真实媒体生产 |
| 超预算时改选替代方案 | 突破用户给定预算 |
| 工具失败时保留已成功步骤 | 把失败步骤记成成功 |
| 幂等防重复保存 | 并发持久化 |
| 失败步骤续跑（加分项）| 多 Agent 协作 |

## 输入

- **主题**（topic）、**预算**（budget，模拟单位）、**截止时间**（deadline）
- 合成素材库（`data/materials.json`）、候选方案模板（`data/candidates.json`）
- 工具费用与耗时表（`data/fees.json`）

## 成功标准（对应考核验收点）

| # | 成功标准 | 判据 |
|---|---|---|
| S1 | 正常完成 | 在预算内选出方案并保存 |
| S2 | 缺预算或截止时间 | `needs_more_info`，不调工具 |
| S3 | 工具失败 | 保留已成功步骤，失败步骤标 `failed`，不记成功 |
| S4 | 预算超限 | 改选替代方案；无解则 `incomplete` + 缺口 |
| S5 | 重复执行 | 同任务只存一份方案 |
| S6 | ReAct 决策 | 模型据工具事实调整动作，≥2 条不同路径 |
| S7 | 步数上限 | 超限返回 `incomplete` |
| S8 | 边界 | 无解不虚报成功；超预算方案绝不保存 |
| S9 | 失败续跑（加分）| 续跑跳过已成功步骤，不重做 |

## 交付结果字段

`任务计划` / `步骤状态`（pending/success/failed/skipped）/ `工具结果` / `费用合计` / `已保存方案或未完成原因`。
